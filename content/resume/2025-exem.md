Exem monitors electromagnetic fields across France (radio, cellular, every
operator). Cities and local authorities rely on its tools for public-health
transparency: measured waves, network coverage, 3D antenna projections, and
the administrative paperwork that follows them. That offer lived in a handful
of small, inconsistent apps; this project merges it into one coherent web
application: site-planning tools, cartography layers, clustered measurement
points and data-exploration panels, all on the same interactive map.

I built it from scratch as the sole front-end in a two-person product team.
Under the map work, the foundation is a Storybook-driven component library:
100+ components implemented from the Figma designs, each built skeleton-first,
so loading states are a property of the system rather than an afterthought.
API types are generated from the OpenAPI specs, so the front-end cannot drift
from the backend contract; i18n was in from day one.

Stack bets: TanStack Start over an ever-heavier Next.js, and React Strict DOM
(close to the DOM and accessible by default, while keeping the cross-platform
door open). A budget cut ended the mission before launch; the front-end was
handed over near-complete to Exem's in-house team.

Exem mesure les champs électromagnétiques partout en France (radio,
téléphonie, tous les opérateurs). Villes et collectivités s'appuient sur ses
outils pour la transparence sanitaire : ondes mesurées, couverture réseau,
projections 3D d'antennes et les dossiers administratifs qui vont avec. Cette
offre vivait dans une poignée de petites applications hétérogènes ; ce projet
les réunit en une seule application web cohérente : outils de planification de
sites, couches cartographiques, points de mesure agrégés et panneaux
d'exploration de données, le tout sur la même carte interactive.

Je l'ai construite de zéro, seul front-end d'une équipe produit de deux
personnes. Sous le travail cartographique, la fondation est une bibliothèque
de composants pilotée par Storybook : plus de 100 composants implémentés
depuis les maquettes Figma, chacun construit skeleton-first, pour que les
états de chargement soient une propriété du système et non une rustine. Les
types de l'API sont générés depuis les spécifications OpenAPI : le front-end
ne peut pas s'écarter du contrat du backend. L'i18n était là dès le premier
jour.

Paris techniques : TanStack Start plutôt qu'un Next.js toujours plus lourd, et
React Strict DOM (proche du DOM et accessible par défaut, tout en gardant la
porte ouverte au cross-platform). Une coupe budgétaire a mis fin à la mission
avant le lancement ; le front-end a été transmis quasi terminé à l'équipe
interne d'Exem.
